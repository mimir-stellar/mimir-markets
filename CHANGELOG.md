# Changelog

All notable changes to Mimir are documented here. The format loosely follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); entries describe the
why, the commit history records the what.

## [Unreleased]

### Added

- **Offline rollback readiness report** ([#943](https://github.com/mimir-stellar/mimir-markets/issues/943)). `npm run report:rollback-readiness` (`lib/ops/rollback-readiness.ts`) shows the predecessor artifacts a rollback needs (pinned contract Wasm digests, runbooks, the rehearsal script, cache-backup inputs and the committed schema snapshot), the schema assumptions it makes about the read index, and the blockers observed, including the findings of the `rollback`-area release gates. Unpinned digests, unevidenced gates and unchecked drift are warnings in develop mode and errors with `--mode=release`; missing files, drift and failed gates are always errors. Read-only and reproducible from a clean checkout: no deployment, database write, chain transaction, network access or credentials, with deterministic output and secret-shape scrubbing. See `docs/ROLLBACK.md`.
- **Deterministic message-hub and citation failure fixtures** ([#937](https://github.com/mimir-stellar/mimir-markets/issues/937)). `tests/fixtures/xmtp/message-hub-failures.ts` and `tests/fixtures/research/citation-failures.ts` pin account changes, unavailable transports, expired private context and every citation failure status without a clock read or a live transport. On the behavior side, `messagesHubVisibleThreads` drops rows that were fetched for a different wallet account (the hub does not unmount on a wallet switch, so the previous account's threads could render while the next fetch was in flight), and `resolveMessagesHubPrivateContext` gates the thread panel on the selected context still belonging to the connected account and being unexpired.
- **Bounded claim history keyed by event identity** ([#781](https://github.com/mimir-stellar/mimir-markets/issues/781)). `mimir-market` now records every successful claim transition (create, each challenge, resolve, cancel, deadline expiry) as its own persistent entry keyed by `(claim_id, seq)`, where `seq` is a per-claim counter that is never reused, so transition references stay stable as new ones are appended. `get_claim_history(claim_id, cursor, limit)` returns at most `MAX_HISTORY_PAGE_SIZE` (50) transitions after `cursor`, reads one entry per returned transition and never the challenger roster, and makes incomplete history explicit: `next_cursor` while more exists, `from_genesis = false` for claims that predate tracking, and `missing_seq` when an archived entry stops the page. An oversized `limit` is refused with the new `HistoryPageTooLarge` (49). Additive only; existing entry points, events and pull-based payouts are unchanged. See `docs/CLAIM_HISTORY.md`.
- **Research-source disagreement report** ([#865](https://github.com/mimir-stellar/mimir-markets/issues/865)). `lib/research/disagreement.ts` compares normalized facts (number, string, boolean; JSON path or regex locators; absolute/relative tolerance) across captured research sources and reports each fact as `agree`, `disagree` or `insufficient`. Each source's cell is `value`, `missing`, `unparseable` or `unavailable`, so a failed, stale or unreadable source is never counted as a dissent. Bounded by `maxSources` (8), `maxFacts` (16), `maxBodyBytes` (512 KiB) and `maxValueChars` (200); overflow is listed as skipped and bodies never appear in the report. See `docs/RESEARCH_DISAGREEMENT.md`.
- **Research gateway results say whether they came from cache** ([#864](https://github.com/mimir-stellar/mimir-markets/issues/864)). `FetchSuccess` now has `acquisition` (`"fetched"` or `"cache"`) and `servedAt`. A cache hit keeps the original `capturedAt` and the content-validation `policyRevision` it was captured under (#1091), and the replay time goes in `servedAt`, so a replay is never shown as a new acquisition; freshness is still judged from `capturedAt`. Cache hits return a copy of the redirect chain, so a caller cannot rewrite the cached entry. `fromCache` is unchanged for existing callers.

### Fixed

- **Source citations keep a stable order when capture times are equal** ([#936](https://github.com/mimir-stellar/mimir-markets/issues/936)). Citations now sort by trust tier, then most recent capture (undated last), then a canonical source identity — the content digest when present, otherwise the normalized URL — instead of the position a source held in the response. The duplicate-collapse pass uses the same comparator, so two asynchronous responses carrying the same sources render the same list. `compareCitations` and `citationSourceIdentity` are exported, and the order is documented in `docs/EVIDENCE_COMMITMENT.md`.
- **A paid x402 response that is lost after settlement can be fetched again without paying twice** ([#851](https://github.com/mimir-stellar/mimir-markets/issues/851)). Settlement claims the transaction hash after the handler runs, so a dropped response left the buyer charged with nothing to show, and every retry was `already_settled`. Each settled payment now gets a durable fulfillment receipt (`x402_fulfillment_receipts`) binding it to the canonical resource digest of the request it bought, first binding wins. The same proof for the same resource, by the same payer, is redelivered within `X402_REDELIVERY_WINDOW_MS` (default 15 min) up to `X402_REDELIVERY_MAX` times (default 3), with no new charge and no second revenue row. A different resource or payer is still refused.

- **The Oracle Reasoning Trace disclosure now announces its state** ([#522](https://github.com/mimir-stellar/mimir-markets/issues/522)). The `EvidenceInspector` toggle button carried no `aria-expanded` and no `aria-controls`, the expanded panel had no id and no label, and the chevron icons were read out as content — so screen-reader users could not tell whether the panel was open, nor which region the button controlled. The button now exposes `aria-expanded` / `aria-controls` (paired through `useId`), the panel is a labelled `region`, the chevrons are `aria-hidden`, and the toggle keeps a visible focus ring.
- **Council passes no longer ship a `NaN` lifetime** ([#519](https://github.com/mimir-stellar/mimir-markets/issues/519)). `COUNCIL_PASS_TTL_MS` was cast straight into `Number()`, so a typo (`10m`), a blank value, a fraction or a negative number flowed into `issuePass()` and back to the buyer as `ttlMs: NaN` / `expiresAt: NaN` *after* the payment had been taken — and a negative value issued an already-expired pass. The lifetime now resolves through `resolveCouncilPassTtlMs()` (`lib/council/pass-ttl.ts`): malformed values fall back to the 10-minute default, values above the cap are clamped to 24 hours, and the TTL the route reports is exactly the one the pass was issued with.

### Changed

- **CI path filters now fail closed** ([#127](https://github.com/mimir-stellar/mimir-markets/issues/127), [#168](https://github.com/mimir-stellar/mimir-markets/pull/168)). CI selects what to run from an allowlist of changed paths instead of one monolithic job: a changed path either maps to a tier (`app`, `agents`, `contracts`, `tests`) and runs that tier's checks, or it matches nothing and is UNKNOWN — and UNKNOWN fails the build. Filters that fail open are worse than none at all: they turn a green check into a lie about what was verified. Every degenerate case therefore resolves to "run more", never "run less":
  - An unclassified path (new top-level directory, unlisted root file, near-miss like `appx/`) fails the paths job and runs all tiers.
  - An undecidable change set (missing event payload, failed fetch, no merge-base) runs all tiers and marks the run red.
  - Doc-only changes (`README.md`, `CHANGELOG.md`, `LICENSE`, `docs/`) are the one explicit "run nothing" outcome.
- Adding a scope is now a reviewed, parity-checked decision: `lib/ci/path-scope.ts` (the tested contract) and `scripts/ci/changed-paths.mjs` (the workflow driver) must stay identical, enforced by `npm run check:driver-parity` and `tests/node/ci-path-scope.test.ts`. A green CI run now means the suites that ran are exactly the suites the change required.
